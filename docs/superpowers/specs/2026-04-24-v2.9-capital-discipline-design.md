# v2.9 — Capital Discipline & Opportunity-Sized Positions

**Date:** 2026-04-24  
**Status:** Approved  
**Version bump:** v2.8 → v2.9

## Context & Problem

The bot has executed 91 closed trades since launch (+$8.75 total P&L, 62.6% win rate). The
core strategy — buy dips, sell rallies — is sound, but capital deployment is broken:

**The pyramiding anti-pattern:**
On Apr 24, the bot opened 10 ETHUSDT positions between $2,310 and $2,318 (a $8 spread,
0.03% apart), deploying $100.25 of a $115 portfolio in a single sideways session. These are
not DCA entries — they are the same price bought 10 times. The root causes:

1. `max_trades_per_day_per_asset = 2` exists in config but is never enforced in code.
2. No minimum price spread between consecutive entries — the bot re-buys on the same candle
   pattern repeatedly.
3. Score 5 buys ($10 at 10% of available) fire constantly because Fear & Greed has been in
   extreme fear (8–16) for 6+ consecutive weeks, firing on nearly every scan.
4. Position size is flat and disconnected from projected opportunity magnitude — a score-5
   probe and a score-8 high-conviction trade both get ~$10.

**Key data findings (91 closed trades):**
- ETH: 66.7% win rate, +$7.77, avg +1.22% — clear outperformer
- BTC: 56.8% win rate, +$0.98, avg +0.29% — marginal
- Best hold window: 12–24h (75% win rate, avg +1.32%)
- Score 6 best performer: 71% win rate, avg +2.37%
- 100% of closes via signal_sell — stop-losses and trailing stops never triggered

## Design Goals

1. Position size must reflect the **magnitude of the projected rally**, not just whether score
   exceeds the minimum threshold.
2. DCA is legitimate and should be preserved — buying at progressively lower prices during a
   genuine dip is the core strategy. Each DCA step should deploy **more** capital as
   conviction deepens.
3. Prevent buying the same price multiple times — entries must be meaningfully lower than
   existing open positions.
4. Each additional DCA entry requires a **stronger signal** (higher score) to justify adding
   to a position.

---

## Architecture

### 1. Opportunity Tiers — Score → Base Size

Replace the current flat buy_light/moderate/strong/maximum buckets with conviction-tiered
sizing:

| Score | Tier | Base % of Deployable | Rationale |
|-------|------|----------------------|-----------|
| 5 | **Probe** | 8% | Weak/single signal — small toe-in |
| 6–7 | **Confirmed** | 28% | Multiple signals aligned — real position |
| 8–9 | **Strong** | 48% | Deep dip + strong technicals — large position |
| 10+ | **Max** | 65% | Maximum conviction — biggest allowed trade |

### 2. DCA Escalation Multiplier

When the bot already has open positions in a symbol, each new entry (at a lower price) gets
a size multiplier — reflecting that a deepening dip with rising conviction warrants more
capital:

| Open positions (before new entry) | Multiplier | Score minimum |
|------------------------------------|------------|---------------|
| 0 | 1.0× | ≥5 |
| 1 | 1.5× | ≥6 |
| 2+ | 2.0× | ≥7 |

**Cap:** No single trade may exceed 50% of available capital (`dca_max_per_trade_pct`).

**Example — ETH drops 6% over 3 sessions, score rises:**
```
Entry 1 (score 5, $2,400):  8% × $115 × 1.0 = $9.20   ← probe
Entry 2 (score 6, $2,352):  28% × $106 × 1.5 = $44.52  ← confirmed dip
Entry 3 (score 7, $2,305):  48% × $61  × 2.0 = $58.56 → capped at $30.50 (50%)
```

**Example — ETH sideways $2,310–$2,318 (today's anti-pattern):**
```
Entry 1 (score 5, $2,318): $9.20  ← allowed
Entry 2 (score 5, $2,313): BLOCKED — spread 0.22% < 2% required
```

### 3. Minimum Entry Spread

New entry only allowed if current price is at least 2% below the **cheapest existing open
entry** for that symbol:

```
spread = (cheapest_entry_price - current_price) / cheapest_entry_price
if spread < 0.02: block
```

This enforces genuine DCA — each step must represent a meaningful new price level.

### 4. max_open_positions_per_asset: 10 → 4

Caps DCA depth at 4 levels. Beyond 4 entries in a single symbol, the position is considered
fully built and no further adds are allowed regardless of signal.

## Implementation

### `config.py` changes

```python
# ScoringConfig — update existing values, add new params:
buy_light_pct: float = 0.08        # Score 5: probe (was 0.10)
buy_moderate_pct: float = 0.28     # Score 6-7: confirmed (was 0.30)
buy_strong_pct: float = 0.48       # Score 8-9: strong (was 0.45)
buy_maximum_pct: float = 0.65      # Score 10+: max conviction (was 0.60)
dca_multiplier_2nd: float = 1.5    # 2nd position multiplier (new)
dca_multiplier_3rd: float = 2.0    # 3rd+ position multiplier (new)
dca_score_min_2nd: int = 6         # Minimum score for 2nd entry (new)
dca_score_min_3rd: int = 7         # Minimum score for 3rd+ entry (new)
dca_max_per_trade_pct: float = 0.50  # Hard cap per single trade (new)

# RiskConfig:
min_entry_spread_pct: float = 0.02   # 2% below cheapest open entry (new)
max_open_positions_per_asset: int = 4  # was 10
```

### `strategy.py` — `calc_buy_amount()`

Add `open_positions: list = None` parameter. Apply DCA multiplier based on
`len(open_positions)`. Cap at `SC.dca_max_per_trade_pct × available_usdt`.

### `risk_manager.py` — `can_buy()`

**Three changes to this file:**

1. Add `SC = config.scoring` at module level (alongside existing `RC = config.risk`).
2. Change signature to add `current_price: float = 0.0` and `buy_score: int = 0`.
3. Replace `db.count_open_positions(symbol)` with `db.get_open_positions(symbol)` so the
   position list is available for the spread check. Derive count via `len()`.

New checks (after the existing `max_open_positions_per_asset` guard):

**Check A — Minimum entry spread:**
```python
# open_positions already fetched above via db.get_open_positions(symbol)
if current_price > 0 and open_positions:
    cheapest = min(p["entry_price"] for p in open_positions)
    spread = (cheapest - current_price) / cheapest
    if spread < RC.min_entry_spread_pct:
        return False, (
            f"{symbol}: precio ${current_price:.2f} no está "
            f"{RC.min_entry_spread_pct:.0%} bajo entry más barato "
            f"${cheapest:.2f} (spread {spread:.2%})"
        )
```

**Check B — Score minimum per DCA step:**
```python
if buy_score > 0 and open_count > 0:
    min_score = (SC.dca_score_min_3rd if open_count >= 2
                 else SC.dca_score_min_2nd)
    if buy_score < min_score:
        return False, (
            f"{symbol}: necesita score ≥{min_score} para "
            f"entrada #{open_count+1} (actual {buy_score})"
        )
```

### `bot.py` — `_execute_buy()`

```python
open_positions = db.get_open_positions(symbol)
amount = strategy.calc_buy_amount(buy_score, available, total, open_positions)

allowed, reason = risk_manager.can_buy(
    symbol, amount, available, total,
    current_price=price, buy_score=buy_score,
)
```
